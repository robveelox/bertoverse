# Historical: upgrade sandbox.habbud.com to v0.4

This document is retained for release history only. Do not use it for a current deployment; follow [V0.10.6_UPGRADE.md](V0.10.6_UPGRADE.md) and [HABBUD_VPS_DEPLOYMENT.md](HABBUD_VPS_DEPLOYMENT.md).

Connect using the established SSH alias and administrator account:

```bash
ssh habbud-server
sudo -i
```

Back up the application and database:

```bash
tar --exclude=node_modules -czf /root/greenroom-pre-v0.4.tgz -C /var/www greenroom
mariadb-dump greenroom > /root/greenroom-pre-v0.4.sql
```

After uploading `greenroom-social-world-v0.4.zip` to `/home/administrator/`:

```bash
unzip -oq /home/administrator/greenroom-social-world-v0.4.zip -d /var/www/greenroom
chown -R greenroom:www-data /var/www/greenroom
cd /var/www/greenroom
sudo -u greenroom npm ci
mariadb greenroom < database/migrations/002_accounts_and_sessions.sql
sudo -u greenroom npm run build
```

Add this block to the existing HTTPS `server` block in `/etc/nginx/conf.d/sandbox.habbud.com.conf`, immediately before the existing `location /` block:

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:3105;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_no_cache 1;
    proxy_cache_bypass 1;
}
```

Validate and restart:

```bash
nginx -t
systemctl reload nginx
systemctl restart greenroom
systemctl status greenroom --no-pager
curl -sS https://sandbox.habbud.com/health
curl -sS https://sandbox.habbud.com/api/auth/session
```

The session response should be `{"user":null}` before signing in. Existing guests continue to work.
