# Historical: upgrade Bertoverse to v0.8.3

This runbook is retained for release history. For the current release use [V0.10.6_UPGRADE.md](V0.10.6_UPGRADE.md).

This runbook matches the current source tree and the existing VPS layout at `/var/www/greenroom`.

## 1. Connect and back up

```bash
ssh habbud-server
sudo -i
tar --exclude=node_modules -czf /root/greenroom-pre-v0.8.3.tgz -C /var/www greenroom
mariadb-dump --single-transaction greenroom > /root/greenroom-pre-v0.8.3.sql
```

Keep the archive and SQL dump until the two-client smoke test is complete.

## 2. Upload and extract

From the development Mac:

```bash
scp ~/Downloads/greenroom-social-world-v0.8.3.zip habbud-server:/home/administrator/
```

On the VPS, extract over the application tree and preserve the production `.env`:

```bash
unzip -oq /home/administrator/greenroom-social-world-v0.8.3.zip -d /var/www/greenroom
chown -R greenroom:www-data /var/www/greenroom
chown greenroom:www-data /var/www/greenroom/.env
chmod 640 /var/www/greenroom/.env
```

The release archive must not contain production secrets. If `.env` was overwritten, restore it before starting the service.

## 3. Apply migrations

On a clean database, apply `001_initial.sql`, `002_accounts_and_sessions.sql`, `003_avatar_lineup.sql`, and `004_v06_rooms_catalog.sql` in that order. On an existing installation, apply only the files that have not already run; never edit an applied migration.

```bash
for migration in /var/www/greenroom/database/migrations/*.sql; do
  mariadb -u greenroom_app -p -h 127.0.0.1 greenroom < "$migration"
done
```

## 4. Install, test, and build

```bash
cd /var/www/greenroom
sudo -u greenroom npm ci
sudo -u greenroom npm run typecheck
sudo -u greenroom npm test
sudo -u greenroom npm run build
```

## 5. Restart and verify

```bash
cp /var/www/greenroom/deploy/greenroom.service /etc/systemd/system/greenroom.service
systemctl daemon-reload
systemctl restart greenroom
systemctl status greenroom --no-pager
curl -sS http://127.0.0.1:3105/health
curl -sS https://sandbox.habbud.com/health
```

Do not overwrite a Certbot-managed HTTPS Nginx vhost. Merge proxy changes from `deploy/sandbox.habbud.com.conf`, run `nginx -t`, and reload only after the test passes.

## 6. Smoke test and rollback

Use two browser sessions to test registration/login, room entry, all eight movement vectors, avatar switching, chat, room creation, navigator visits, catalog purchase, inventory, reconnect, and logout. If the release fails, stop the service, restore the application archive and SQL dump, rebuild with the previous lockfile, and restart.
