# Upgrade Bertoverse to v0.10.6

Use this runbook when upgrading the existing `/var/www/greenroom` installation from 0.10.5. It assumes the SSH alias and service names already used by the VPS.

## 1. Connect and back up

```bash
ssh habbud-server
sudo -i
tar --exclude=node_modules -czf /root/greenroom-pre-v0.10.6.tgz -C /var/www greenroom
mariadb-dump --single-transaction greenroom > /root/greenroom-pre-v0.10.6.sql
```

Keep both files until the two-client smoke test is complete.

## 2. Upload from the development Mac

```bash
scp ~/Downloads/bertoverse-v0.10.6.zip habbud-server:/home/administrator/
```

## 3. Extract without replacing secrets

```bash
unzip -oq /home/administrator/bertoverse-v0.10.6.zip -d /var/www/greenroom
chown -R greenroom:www-data /var/www/greenroom
chown greenroom:www-data /var/www/greenroom/.env
chmod 640 /var/www/greenroom/.env
```

The archive must not contain production `.env` values. If it does, stop and restore the previous `.env` from the backup before continuing.

## 4. Apply the two new migrations

Only run a migration that is not already applied in the target database:

```bash
mariadb -u greenroom_app -p -h 127.0.0.1 greenroom < /var/www/greenroom/database/migrations/008_account_security.sql
mariadb -u greenroom_app -p -h 127.0.0.1 greenroom < /var/www/greenroom/database/migrations/009_v0106_purchase_idempotency.sql
```

If the project has a migrations ledger in a later release, use that ledger rather than rerunning files. Never edit an applied migration.

## 5. Install, verify, and build

```bash
cd /var/www/greenroom
sudo -u greenroom npm ci
sudo -u greenroom npm run typecheck
sudo -u greenroom npm test
sudo -u greenroom npm run build
```

If npm blocks install scripts, approve only `argon2` and `esbuild`, then run `sudo -u greenroom npm rebuild argon2` and repeat the build.

## 6. Restart and verify

```bash
cp /var/www/greenroom/deploy/greenroom.service /etc/systemd/system/greenroom.service
systemctl daemon-reload
systemctl restart greenroom
systemctl status greenroom --no-pager
curl -sS http://127.0.0.1:3105/health
curl -sS https://sandbox.habbud.com/health
```

Do not replace the active Certbot-managed HTTPS Nginx vhost. Merge any security-header or proxy-timeout changes from `deploy/sandbox.habbud.com.conf`, run `nginx -t`, and reload Nginx only after the test passes.

## 7. Smoke test and rollback

Use two browser sessions to test login, movement in all eight directions, chat, profile cards, phone, wardrobe, catalog, wallet, logout, reconnect, and duplicate-presence prevention. Check `journalctl -u greenroom` and the Nginx error log.

For rollback, stop `greenroom`, restore `/root/greenroom-pre-v0.10.6.tgz` and the SQL dump, rebuild with the previous lockfile, and restart. Keep the v0.10.6 migration state documented; do not delete production tables to force a rollback.
