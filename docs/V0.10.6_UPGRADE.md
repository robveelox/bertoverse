# Bertoverse v0.10.6 security and stability upgrade

This release is a code-only hardening update on top of v0.10.5. It does not
drop, rename or rewrite existing tables. Take a rollback copy before replacing
the application files:

```bash
ssh habbud-server
sudo -i
tar --exclude=node_modules -czf /root/greenroom-pre-v0.10.6.tgz -C /var/www greenroom
mariadb-dump greenroom > /root/greenroom-pre-v0.10.6.sql
```

Upload the archive to `/home/administrator/`, then run:

```bash
cd /var/www/greenroom
unzip -oq /home/administrator/bertoverse-v0.10.6.zip -d /var/www/greenroom
chown -R greenroom:www-data /var/www/greenroom
chmod 640 /var/www/greenroom/.env
sudo -u greenroom npm ci
sudo -u greenroom npm install-scripts approve argon2 esbuild
sudo -u greenroom npm rebuild argon2
sudo -u greenroom npm run typecheck
sudo -u greenroom npm test
sudo -u greenroom npm run build
systemctl daemon-reload
systemctl restart greenroom
systemctl status greenroom --no-pager
curl -sS http://127.0.0.1:3105/health
```

If the existing Nginx vhost has already been modified by Certbot, do not
overwrite it with the HTTP-only template. Merge the security headers,
`client_max_body_size`, and proxy timeout directives from
`deploy/sandbox.habbud.com.conf` into the active HTTP and HTTPS server blocks,
then validate and reload Nginx:

```bash
nginx -t
systemctl reload nginx
```

The v0.10.5 migration remains required if it has not already been applied:

```bash
mariadb -u greenroom_app -p -h 127.0.0.1 greenroom < database/migrations/008_v0105_security_settings.sql
```

Apply the v0.10.6 purchase retry migration as well:

```bash
mariadb -u greenroom_app -p -h 127.0.0.1 greenroom < database/migrations/009_v0106_purchase_idempotency.sql
```
